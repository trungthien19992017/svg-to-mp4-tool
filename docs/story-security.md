# Story execution boundaries

Scene code is untrusted even when generated by ChatGPT. MVC never evals/executes it; neither does Python/Node. Preview runs in a sandboxed opaque-origin iframe from loopback port 5189; main application is on 5188. Port 5189 exposes a small read-only runtime/asset surface, never application API/session/job endpoints. Main-origin runtime HTML is blocked. Main and preview CSPs restrict resource loading; iframe has scripts permission but no same-origin, forms, popups or top navigation privileges. PostMessage handlers check exact window source, channel and per-load random token, and only accept data (no code).

Export uses sandbox-enabled Chromium with all requests fulfilled from the immutable project snapshot or an exact trusted-runtime allowlist. File URLs and other origins are aborted, offline mode is on, service workers/downloads are disabled. No Python, Node, shell, filesystem or secret-bearing host bindings are exposed to scene JavaScript. Common nondeterministic/network APIs are disabled in runtime in addition to source lint. Keep Chrome/Playwright updated and do not disable Chromium sandbox to fix an environment issue.

The .NET Story worker uses a Windows 64-bit Job Object: kill child processes on close, at most 32 processes, 2 GiB per process, 4 GiB total committed memory, 30-minute process CPU budget and wall-clock cancellation based on story duration (15 minutes to 2 hours). This boundary contains Python, its Playwright Node driver, Chromium and FFmpeg descendants. Guard setup failure kills the worker and fails the job; imported JS export is not enabled on other platforms until an equivalent OS/container boundary is configured. These limits and cancellation have not yet been exercised in the current blocked approval environment; verify before treating this build as production-ready.

Preview still uses the user's installed browser process management. A hostile script can consume renderer CPU; browser sandbox, separate origin and CSP are real boundaries, but not a per-preview OS memory quota. This local desktop workflow is not a public multi-tenant arbitrary-code service. Use an isolated account/VM/container with no secrets for stronger hostile-code workloads; do not expose these ports externally.

ZIP limits are enforced before publishing a revision; stream expansion is bounded, paths are validated, symlinks/case duplicates rejected. Imports write only under generated revision directories. SVG assets reject scripts/event attributes/foreignObject/external href. Resource routes canonicalize paths and stay under the selected snapshot. Media decoding also remains inside the worker's OS job; FFmpeg audio inputs use explicit formats and protocol restrictions.

Logs: user-facing errors are concise; `renderer.log`, `encoder.log`, `audio.log`, `result.json` live in each job workspace. Cancellation kills the process tree and removes partial MP4 files. Source assets/revisions are retained; no automatic deletion of existing user projects or render history is performed.
